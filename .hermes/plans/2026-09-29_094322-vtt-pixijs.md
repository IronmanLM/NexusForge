# Module VTT PixiJS Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Ajouter aux parties Nexus Forge un module VTT simple mais extensible, basé sur PixiJS, avec carte, grille carrée/hexagonale, pions libres, brouillard manuel et synchronisation temps réel.

**Architecture:** Le VTT devient un sous-module de `SessionViewPage` avec un onglet dédié et une route plein écran. La V1 reste générique et découplée des fiches/systèmes, mais le modèle de données prévoit une liaison future avec personnages, initiative, mesures, lumière et automatisations. PixiJS est utilisé pour le rendu performant des cartes, tokens, couches et masques ; React garde l’interface/outillage autour du canvas.

**Tech Stack:** React 18, TypeScript, Vite, PixiJS, backend Express, persistance `state.json`, synchronisation temps réel via canal dédié à définir (WebSocket/SSE selon audit backend), ressources Nexus Forge existantes.

---

## Contexte et décisions actées

- Choix moteur : **PixiJS** directement, car le VTT doit évoluer sur plusieurs versions.
- Licence PixiJS : MIT d’après le dépôt officiel PixiJS et les sources publiques consultées.
- V1 fonctionnelle souhaitée :
  - carte/image ;
  - grille carrée ou hexagonale ;
  - taille de grille personnalisable ;
  - pions libres/manuels ;
  - brouillard de guerre manuel ;
  - masques rectangulaires et polygonaux préparés en amont ;
  - vue MJ distincte de la vue joueur ;
  - côté MJ, le brouillard ne cache pas l’image, il sert de surcouche indicative ;
  - côté joueur, le brouillard masque réellement ;
  - upload direct d’image depuis le VTT et sélection depuis les ressources Nexus Forge ;
  - temps réel indispensable dès V1 ;
  - les joueurs peuvent déplacer leur pion seulement si le MJ l’autorise ;
  - intégration dans un onglet de partie + mode plein écran/projection.
- Priorités produit :
  1. Préparation MJ hors session.
  2. Présentiel / projection.
  3. En ligne temps réel.

## Points d’architecture à trancher avant codage

### Synchronisation temps réel

Comparer rapidement les options existantes dans le backend :

- WebSocket natif ou `ws` : meilleur pour événements bidirectionnels temps réel.
- Server-Sent Events : simple pour diffusion serveur → clients, mais moins naturel pour mouvements joueurs → serveur.
- Polling court : facile, mais moins fluide et moins adapté au VTT.
- CRDT/Yjs : puissant pour offline/collaboratif, probablement trop lourd pour V1.

**Recommandation initiale :** WebSocket dédié au VTT, avec persistance des actions importantes dans `state.json`. Garder la compatibilité offline-first en enregistrant les scènes VTT comme état durable, pas comme simple flux éphémère.

### Modèle de données V1

Ajouter un bloc VTT au modèle de partie, probablement sous chaque session :

```ts
type VttScene = {
  id: string;
  name: string;
  mapResourceId: string | null;
  mapImageUrl: string | null;
  mapWidth: number;
  mapHeight: number;
  grid: {
    enabled: boolean;
    type: 'square' | 'hex';
    size: number;
    color: string;
    opacity: number;
    offsetX: number;
    offsetY: number;
  };
  fog: {
    enabled: boolean;
    mode: 'hidden-by-default' | 'visible-by-default';
    shapes: VttFogShape[];
  };
  tokens: VttToken[];
  permissions: {
    playersCanMoveOwnTokens: boolean;
  };
  createdAt: string;
  updatedAt: string;
};

type VttFogShape = {
  id: string;
  type: 'rectangle' | 'polygon';
  mode: 'reveal' | 'hide';
  points: Array<{ x: number; y: number }>;
};

type VttToken = {
  id: string;
  name: string;
  imageResourceId: string | null;
  imageUrl: string | null;
  x: number;
  y: number;
  width: number;
  height: number;
  rotation: number;
  ownerUserId: string | null;
  visibleToPlayers: boolean;
  locked: boolean;
};
```

### PixiJS rendering layers

Rendu par couches :

1. `mapLayer` : carte/image.
2. `gridLayer` : grille carrée/hexagonale.
3. `fogLayer` : brouillard/masks.
4. `tokenLayer` : pions.
5. `selectionLayer` : contours, handles, previews de formes.
6. `uiOverlayLayer` : curseur/outil actif si nécessaire.

Vue MJ : image toujours visible, fog semi-transparent / hachuré / coloré.
Vue joueur : fog appliqué en masque réel.

## Risques et arbitrages

### PixiJS + React

PixiJS doit posséder le canvas et les objets rendus. React doit piloter l’état et l’outillage, mais ne doit pas rendre chaque token comme composant DOM si on veut garder de bonnes performances.

### Temps réel + offline-first

Ne pas confondre :
- flux temps réel éphémère pour fluidité ;
- état durable de scène pour persistance/reconnexion/offline.

La V1 doit persister les changements importants, même si les mouvements transitent en temps réel.

### Brouillard

Le brouillard joueur doit être une vraie contrainte visuelle. Le brouillard MJ doit être un calque indicatif, jamais bloquant.

### Hex grid

La grille hexagonale introduit des calculs de coordonnées plus complexes. Garder V1 sur rendu/alignement simple, sans automatisation de portée/distance avancée.

### Permissions

Chaque action VTT doit être validée côté backend, pas seulement côté frontend.
